# とち介商品券2026 マップ 運用手順

このアプリを**運用する人**のための手順書。設計の理由や制約は `CLAUDE.md` にある。

- 利用者の端末に何が要るか → `doc/動作環境.md`
- サーバーに何が要るか（別のサーバーへ移すとき）→ `doc/サーバー要件.md`

公開先: https://www.ngmix.com/tochisuke/

---

## 1. 全体像

```
data/raw/*.xlsx （市が公開した原本・絶対に加工しない）
      │ bun run import:excel
      ▼
data/shops.csv  ★ 正本。直したいことは全部ここに書く
      │ bun run import:csv
      ▼
public/shops.json （アプリが読むデータ）
      │ bun run build
      ▼
out/ の中身 → FTP で ~/www/ngmix.com/tochisuke/
```

**`data/shops.csv` が正本。** Excel は「市が何を出したか」の記録でしかなく、
取り込んでも CSV の店舗情報を書き換えることはない。

| ファイル | 役割 | 人が開くか |
| --- | --- | --- |
| `data/raw/*.xlsx` | 市の原本。受け取ったまま置く | 見るだけ |
| `data/shops.csv` | **正本。ここを編集する** | **開く** |
| `data/excel-baseline.json` | 原本の控え（差分の計算に使う） | 開かない |
| `data/geocode-cache.json` | 住所→座標の記録 | 開かない |
| `data/places-cache.json` | 店名→座標の記録 | 開かない |
| `public/shops.json` | 生成物。これが配信される | 開かない |

## 2. よく使うコマンド

```bash
bun run import:csv       # CSV を直したあと。JSON を作り直す（API を叩かない）
bun run geocode          # 住所を変えた・店が増えたあと。座標を取って JSON まで作る
bun run build            # 公開用の out/ を作る
bun run preview          # out/ を確認する（http://localhost:4000/tochisuke/）
bun dev                  # 開発サーバー（http://localhost:3000/tochisuke/）

bun run import:excel -- data/raw/新しいファイル.xlsx   # 市から新しい版が届いたとき
bun test                 # テスト
```

**`bun dev` を動かしたまま `bun run build` を実行しない。** どちらも `.next/` を使うため、
dev サーバーが壊れて画面が「読み込み中…」で止まる。止めてからビルドするか、ビルド後に dev を再起動する。

**CSV を Excel で開いたままコマンドを実行しない。** 書き込みに失敗する。

## 3. 加盟店リストを直す

`data/shops.csv` を Excel（または表計算ソフト）で開いて直し、`bun run import:csv` を実行する。

### 列の役割

**誰が書く列かが決まっている。** 機械の列を手で書いても次の実行で上書きされる。

| 列 | 書くのは | 中身 |
| --- | --- | --- |
| 屋号 / フリガナ / 住所 / 電話番号 / 業種 / のぼり旗の色 | **人だけ** | 機械は読むだけ。Excel を取り込んでも上書きされない |
| 緯度 / 経度 | 機械 | 座標。**出どころが `人` の行だけは機械が触らない** |
| 座標の出どころ | 機械 | `店名` / `住所` / `住所を書き換え` / `人` |
| 確認 | 機械が `要確認` を立て、**人が `済` か `非表示` にする** | 空欄 / `要確認` / `済` / `非表示` |
| 確認事項 | 機械 | なぜ確認が要るのか。毎回書き直される |
| メモ | **人だけ** | なぜ直したかの記録。機械は一切触らない |

- 業種は `C.小売業` の形。のぼり旗の色は `中小店舗/黄色・青色` か `大型店舗/青色`。
- **行を消さない。** 載せたくない店は `確認` を `非表示` にする（後述）。
- 屋号が空の行は無視される。

### 確認列の使い方

機械が「人が見ないと判断できない行」に `要確認` を立てる。中身を見て問題なければ `済` と書く。

| 値 | 意味 |
| --- | --- |
| 空欄 | 確認することが無い |
| `要確認` | 機械が判断を保留した。`確認事項` に理由が出ている |
| `済` | 人が見て問題なしと判断した |
| `非表示` | **アプリに出さない**（後述） |

**`済` は「そのときの確認事項を見て判断した」という意味。** 住所を直して座標が変わるなど
状況が変われば自動で `要確認` に戻り、`前回の確認後に内容が変わった` が付く。
何も変わらなければ `済` のまま静かになる。

**市が原本の誤りを直して `原本と違う: …` が消えた行は、`要確認` に戻らず空欄になる。**
見るべきものが無いので印を付けない（市が直すたびに理由なしの印が増えると、印が読み飛ばされる）。

自分の言葉でメモを残したいときは**メモ欄**に書く。`確認事項` は機械が毎回書き直すので消える。

### 店をアプリに出したくないとき（非表示）

閉店した、実体が無い、といった店は `確認` 列に **`非表示`** と書く。

- `public/shops.json` に出なくなり、アプリの検索にも地図にも出ない
- 行は残るので、なぜ非表示にしたかをメモに残せる
- その行は機械が素通りする（座標も引かない＝無駄な課金もしない）
- 戻したくなったら `非表示` を消すだけ

**行ごと消さないこと。** 消すと記録が失われ、次に Excel を取り込んだとき新規店として復活する。

### 座標を手で入れたいとき

機械がどうしても正しい位置を出せない店は、地図で調べた座標を入れられる。

1. `緯度` と `経度` に値を入れる（例: `36.3826` / `139.7333`）
2. **`座標の出どころ` に `人` と書く** ← これを忘れると次の実行で上書きされる
3. なぜその座標にしたかを `メモ` に残す
4. `bun run import:csv`

## 4. 市から新しい Excel が届いたとき

1. **原本をそのまま `data/raw/` に置く。** 加工しない。
   ファイル名の先頭に受領日を付けると世代が並んで分かりやすい（例: `2026-10-01-加盟店一覧.xlsx`）。
2. 取り込む。

```bash
bun run import:excel -- data/raw/2026-10-01-加盟店一覧.xlsx
```

3. **報告を読む。** 何が起きたかが出る。

| 報告 | CSV への影響 | やること |
| --- | --- | --- |
| 原本に新しく載った店 | **行が足される** | 座標を取る（次項） |
| 原本側で値が変わった列 | **据え置き** | 取り込むなら CSV を手で直す |
| CSV が原本と違うままの列 | **据え置き** | こちらの修正が残っている。そのままでよければ何もしない |
| 今回の原本から消えた店 | **残る** | 掲載終了なら `確認` を `非表示` に |
| 人が CSV から消していて原本にはまだある店 | 復活しない | 意図どおりか確認 |

4. 新しい店があれば座標を取る。

```bash
bun run geocode
```

5. `確認` が `要確認` の行を片付ける（見て `済` にする）。
6. 公開する（第 6 章）。

**取り込んでも既存店の屋号・住所・電話番号などは絶対に書き換わらない。** これは仕様。
原本との食い違いは `確認事項` に `原本と違う: 住所（原本は「…」）` として残り続ける。

## 5. 座標を取り直す

住所を直した、店が増えた、というときに実行する。

```bash
bun run geocode
```

- **すでに取得済みの住所・店名は問い合わせない。** 何度実行しても課金は増えない。
- 座標は 4 段構えで決まる（確かな順）。

| 段 | 手段 |
| --- | --- |
| 1 | CSV の座標（出どころが `人` の行） |
| 2 | 店名で Google Places を引く（店そのものの位置） |
| 3 | 住所をそのまま Geocoding |
| 4 | 住所を機械的に書き換えて引き直す |

- 決まらなかった店は報告に出る。Google の候補があれば座標付きで示されるので、
  地図で確かめて確かなら CSV に手入力する（第 3 章）。
- `.env.local` に `GEOCODING_API_KEY` が要る。

## 6. 公開する

```bash
bun run build     # out/ を作る（bun dev は止めておく）
bun run preview   # http://localhost:4000/tochisuke/ で確認
```

確認できたら **`out/` の中身**を FTP で転送する。

| | |
| --- | --- |
| 転送先 | `~/www/ngmix.com/tochisuke/` |
| 転送するもの | **`out/` の中身**（`out/` フォルダごとではない） |

- `_next/` 配下も一式上げる。HTML だけ更新すると参照先が無く真っ白になる。

### 検索エンジンから見つけてもらうために

- **`www.ngmix.com` のトップページからのリンクを消さないこと。** これが無かった時期に
  「とち介商品券 どこで使える」の検索結果から完全に消え、リンクを足して戻った実績がある。
- **一度だけの作業**: ドメイン直下の `robots.txt`（WordPress 側）に次の 1 行を足すか、
  Google Search Console でサイトマップを送信する。
  ```
  Sitemap: https://www.ngmix.com/tochisuke/sitemap.xml
  ```
- 表示される文言（タイトル・説明・SNS カード）は `src/app/layout.tsx` にある。
  変えたら**再ビルドと `out/` 全体の転送が必要**（`shops.json` だけでは反映されない）。

### 反映されないときはキャッシュを疑う

**古い内容が出続けるのはほぼキャッシュ。** ファイルによって事情が違う。

| ファイル | 古いまま出るか | 理由 |
| --- | --- | --- |
| `_next/static/…` の JS・CSS | **出ない** | ファイル名に内容のハッシュが付くので、変われば別名になる |
| `index.html` | **出うる** | 名前が変わらない |
| `shops.json` | **出うる** | 名前が変わらない。実行時に取得している |

自分で確認するときは**スーパーリロード**（`Ctrl+Shift+R`）。
開いたままのタブは古い JavaScript を保持し続けるので、作り直したら必ず読み込み直す。

利用者側は、しばらく経てば新しいものを取りに行く。急いで行き渡らせたい場合はサーバ側の
キャッシュ設定の話になるが、それはこのリポジトリの範囲外（所有者が別途管理）。

### データだけ更新するとき

**`public/shops.json` の 1 ファイルを差し替えるだけでよい。** 再ビルドもコード転送も要らない。

```
CSV を直す → bun run import:csv → public/shops.json だけ FTP で差し替え
```

画面の見た目や動きを変えたときだけ、`bun run build` して `out/` を一式上げ直す。

## 7. API キーとお金

キーは 2 本ある。**用途が違うので混ぜない。**

| | 地図表示用 | 取り込み用 |
| --- | --- | --- |
| 変数 | `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` | `GEOCODING_API_KEY` |
| 公開されるか | **される**（ビルド成果物に埋め込まれる） | されない |
| 制限 | ウェブサイト（HTTP リファラー） | IP アドレス |
| 許可する API | Maps JavaScript API **のみ** | Geocoding API + Places API (New) |

**地図表示用キーのリファラーは `https://www.ngmix.com/*`。**
`/tochisuke/` のような**パスを含めてはいけない** — ブラウザがパスを送らないため、
正しいアクセスまで弾かれて地図が出なくなる（`RefererNotAllowedMapError`）。

無料枠（2026 年 8 月時点）:

| API | 無料枠 | このアプリの使い方 |
| --- | --- | --- |
| Maps JavaScript API | 10,000 map loads / 月 | 地図タブを最初に開いた回数だけ（タブを往復しても増えない） |
| Geocoding | 10,000 / 月 | 取り込み時のみ。取得済みは 0 |
| Places Text Search | 5,000 / 月 | 取り込み時のみ。取得済みは 0 |

Cloud Console で**割り当て上限と予算アラート**を設定しておくと、万一のとき課金が青天井にならない。

## 8. 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 地図が出ない | API キーのリファラー制限。ブラウザのコンソールに `RefererNotAllowedMapError` などが出る |
| ピンが出ない | Map ID（`NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID`）。設定後は**再ビルドが必要** |
| 更新が反映されない | ブラウザキャッシュ。`shops.json` を転送したか |
| 画面が真っ白 | `_next/` を転送し忘れていないか |
| 古いスマホで「読み込み中…」のまま止まる | 端末が対応外。下の「対応ブラウザ」を見る |
| dev サーバーが「読み込み中…」で止まる | `bun dev` 中に `bun run build` した。dev を再起動する |
| 座標が消えた | 住所を変えると座標を取り直す。`bun run geocode` |
| 手で入れた座標が消えた | `座標の出どころ` が `人` になっているか |
| CSV が文字化けする | BOM 付き UTF-8 で保存されているか（Excel は「CSV UTF-8」で保存） |

### 対応ブラウザ

**詳しくは `doc/動作環境.md`。** 問い合わせ対応で要るのは次の 3 点。

- 一覧・検索は **iPhone は iOS 12 以上、Android は Chrome 64 以上**。
  **地図タブだけはかなり新しい端末が必要**（Google Maps 側の方針）。
- **対応外の端末では画面に理由が出る。**「お使いのブラウザでは表示できません…」と
  表示されたら、アプリの不具合ではなく端末が古い。
- **iPhone に Chrome を入れても直らない。** iOS 上のブラウザは中身が全部 iOS 同梱の
  ものなので、Chrome と表示されても古い Safari と同じ動きになる。

**「読み込み中…」のまま何分も止まる場合**は端末が古いだけでなく、
`_next/` の転送漏れでも起きる。ビルドし直したら `_next/` も一式アップロードすること。
